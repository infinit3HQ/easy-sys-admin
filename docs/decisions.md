# Decisions

The main technical choices behind easy-sys-admin, with the reason for each and what was turned down. Add a row when you make a choice that a future contributor would otherwise question. Older notes are in [archive/](archive/).

| Topic            | Decision                                                                                                                                                                            | Why                                                                                                                                           | Turned down                                                                       |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Repository       | One pnpm + Turborepo monorepo: `apps/esa`, `apps/web`, `packages/api`, shared `tsconfig` and `eslint-config`, one pnpm catalog                                                      | One change can touch the contract, the Go server and the UI and be checked together                                                           | Separate repositories                                                             |
| Backend language | Go for the control plane, CLI and helper                                                                                                                                            | One static binary per role, cross-compiles for amd64 and arm64, good SSH library                                                              | A TypeScript backend                                                              |
| Frontend         | TanStack Start with React 19, Tailwind CSS 4 and shadcn/ui                                                                                                                          | Server rendering plus a typed router; the same app serves the landing page, the board and MCP                                                 |                                                                                   |
| Lint and format  | ESLint and Prettier for TypeScript, `gofmt` and `go vet` for Go                                                                                                                     | Familiar tools with shared configs                                                                                                            | Biome                                                                             |
| Database         | PostgreSQL through GORM, schema from the models with AutoMigrate under an advisory lock; hand-written SQL where GORM is awkward                                                     | Multi-user from the start; no separate migration tool to run                                                                                  | SQLite (first draft), sqlc, Atlas (its community build lacks the features needed) |
| API contract     | `packages/api/openapi.yaml` first; Go server, Go client and TypeScript types generated from it                                                                                      | One description that the web app, CLI and MCP all follow; CI fails when generated code drifts                                                 | Hand-written clients                                                              |
| Reaching servers | SSH as a restricted `esa` user that can only run `esa-helper` through sudo, with a pinned host key                                                                                  | No agent listening on servers; the key cannot run arbitrary commands as root                                                                  | Storing root logins and running shell commands (first draft); an always-on agent  |
| Enrollment       | A pasted one-time command, or a one-time sudo login that is forgotten unless the owner keeps it                                                                                     | Works for servers esa cannot reach with a login yet, and for ones it can                                                                      |                                                                                   |
| Upgrades         | A transient systemd unit per upgrade; servers in batches of a group-set size (1 by default), the control plane host alone; stop after a set number of failed servers (1 by default) | Survives dropped SSH and control plane restarts; a bad update stops before it spreads; a large group can finish in an hour instead of a night | Running apt inside the SSH session                                                |
| Helper updates   | Reinstall over a sudo login; no self-update action                                                                                                                                  | A self-update action would let the `esa` key install any binary as root                                                                       |                                                                                   |
| MCP              | Streamable HTTP at `/mcp` in the web app, TypeScript SDK, calling the API with the caller's token                                                                                   | The agent gets exactly what its token allows; no second permission system                                                                     | A Go MCP server                                                                   |
| MCP and logs     | A token with `logs:read` never gets `start_run`                                                                                                                                     | Log text is written by whatever runs on a server and could steer an agent                                                                     |                                                                                   |
| One origin       | The web server proxies `/api`, `/auth` and `/enroll` to the control plane                                                                                                           | One hostname, one cookie, no CORS                                                                                                             | Exposing the control plane on its own hostname                                    |
| Sign-in          | Password, Google and any OIDC provider, set by environment; a dev login on loopback only                                                                                            | Self-hosters pick what they have                                                                                                              |                                                                                   |
| Organizations    | Each user has one private personal space. An organization owns the fleet and has owner, admin, and viewer roles. Extra teams grant admin on chosen groups and own nothing         | Personal servers stay private. Inside an organization, access to a group is one setting, and each check uses one role on that group           | Teams that own their own servers. Per-server permissions                          |
| Sharing          | Share a whole group with another organization, at `view` or `operate`. A personal space can share a group out and cannot receive one                                               | Access follows the group's servers and schedules, so moving a server in or out changes access                                                 | Sharing single servers                                                            |
| Deploy           | One compose stack behind Traefik with no published ports; GitHub Actions on a self-hosted runner writes the env file per job                                                        | Nothing listens on the host except Traefik; secrets live in the GitHub `production` environment                                               | Building images locally and pushing them                                          |
| Configuration    | Every setting is an environment variable                                                                                                                                            | One copy of the code deploys anywhere                                                                                                         | Config files                                                                      |
| Metrics endpoint | `GET /metrics` on the control plane in the Prometheus text format, written by hand, without login, not proxied by the web app; counts only, with fixed labels                       | The port is internal only, so there is no token to manage; no new dependency; no names can leak through labels                                | `prometheus/client_golang`; serving it through the public web server              |
| Polling at scale | 64 polls at once by default; unreachable servers polled every 5 minutes; TCP connect timeout (5 s) separate from the SSH handshake timeout (15 s)                                   | A status call takes about 1.25 s, so 8 workers stopped near 290 servers per minute, and each down server held a worker for 15 s every minute  | Spreading polls over several minutes; a poll interval per server                  |
| Browser shell    | No terminal in the web app. A shell stays on the operator's own SSH client                                                                                                          | The `esa` key cannot allocate a terminal. A stolen browser session or a script bug would otherwise become a root shell on every server        | Proxying SSH, or a kept sudo login, through the board                             |
| Exposure summary | Once an hour, store sockets listening on all interfaces, SSH auth flags, the firewall name, and counts of extra uid 0 accounts and `NOPASSWD ALL` rules. That list is not a reachability check. Alert when such a socket or an SSH key appears, and when a security update has been waiting 7 days. The full report stays live | The board can show what is exposed, and a notice fires when the picture changes, without keeping user lists, login addresses, or ban lists | A scanner, saving `/etc/shadow` or authorized keys, alerting because password login is on |
