# Decisions

The main technical choices behind easy-sys-admin, with the reason for each and what was turned down. Add a row when you make a choice that a future contributor would otherwise question. Older notes are in [archive/](archive/).

## Defaults for remaining roadmap work

Chosen on 17 November 2026 under the owner's instruction to decide for security and ease of use. These are implementation requirements, not a claim that the features below have shipped.

- A notice can have one assignee, or remain unassigned. An admin assigns an active member of the owning space. Assignment grants no extra access. Removing a member clears their assignments and records the change.
- A group can require two distinct current admins to approve a plan. The default stays one approval. Both approvals require a recent browser sign-in and cover the same frozen plan. Tokens cannot approve or bypass the requirement. There is no emergency bypass; changing the group policy requires a person and an audit entry.
- Reviewing a critical notice records that someone saw it. It does not silence future critical events. Maintenance windows and daily summaries must not delay critical notices.
- Helper compatibility follows the protocol, advertised actions, and report revision. A compatible older helper can keep working. An incompatible helper is clearly marked and cannot perform unsupported work. Reinstallation remains an explicit admin action.
- Backup support stops at collecting and explaining evidence. Esa will not run a restore or claim that a successful backup can be restored.
- External reachability evidence comes from probes an operator runs. No public probe service is enabled automatically. Missing or stale probe evidence is unknown.
- Hosted retention will default to 365 days for audit entries and 90 days for superseded scanner reports and resolved notices. Run reports and backup idempotency receipts stay until account deletion. Unresolved notices stay until resolved. These defaults need implementation and publication before hosted pruning is enabled. Self-hosted retention remains controlled by environment variables.
- Outbound HTTPS polling supports systemd hosts on amd64 and arm64. A credential identifies one server and generation, commands expire, and claims are not replayed. Rocky Linux 9 with DNF 4 and dnf-utils is the first RPM scope. Native container package operations and a live outbound playground connection are verified. A Rocky VM reboot and a production rollout remain deployment checks.

The Grype/Trivy comparison is complete. Grype remains optional and operator-supplied; scanners and vulnerability databases are not redistributed by esa. Hosted retention is 365 days for audit rows and 90 days for resolved notices and superseded scan history once explicitly enabled. Unresolved notices, latest scan evidence, run reports, and backup receipts remain. The privacy page publishes this scope. Both retention settings default off.

## Production and nightly build channels

The owner requested both channels on Server One using the existing runner. Main publishes stable images and deploys production after checks. Nightly publishes preview images and deploys its own project, database, keys, and sign-in allow list. Both images must build before channel aliases move. Deployments pin digests rather than pulling a moving tag. The first nightly account is claimed locally before the web route is exposed. Shared-host nightly services have resource limits, but a shared Docker daemon is not a security boundary against hostile code. PRs never reach this runner. Public GHCR images and source builds remain two equal self-hosting options.
