# AGENTS.md: apps/web

This is the TanStack Start app. It serves the landing page, the board under `/app`, and the MCP endpoint at `/mcp`. It also proxies `/api`, `/auth`, and `/enroll` to the Go control plane, so one origin serves everything. The web app holds no data and makes no permission decisions. The control plane does both. Use the files and helpers named below rather than adding new ones.

## Routes

File-based routing in `src/routes`. `src/routeTree.gen.ts` is generated by the TanStack router plugin during `dev` and `build` (or `pnpm --filter @esa/web generate`). Never edit it by hand.

- `__root.tsx`: HTML shell, global head, styles.
- `index.tsx`: landing page.
- `login.tsx`: sign-in page.
- `invite.$token.tsx`: accept a team invite.
- `share.$token.tsx`: accept a shared group.
- `healthz.ts`: health of the web server and its link to the control plane.
- `mcp.ts`: MCP over Streamable HTTP (`GET`, `POST`, `DELETE`), handled by `server/mcp.ts`.
- `api/$.ts`, `auth/$.ts`, `enroll/$.ts`: proxy to the control plane through `server/proxy.ts`.
- `app/route.tsx`: layout for the signed-in app. Redirects to `/login` without a session. Sidebar, space switcher, `useRole`.
- `app/index.tsx`: the board.
- `app/servers/new.tsx`, `app/servers/$serverId.tsx`: add a server, server page with tabs.
- `app/groups/index.tsx`, `app/groups/new.tsx`, `app/groups/$groupId.tsx`: groups, new group, group page.
- `app/runs/index.tsx`, `app/runs/$runId.tsx`: run history, one run.
- `app/alerts.tsx`, `app/activity.tsx`, `app/team.tsx`, `app/settings.tsx`: alerts, audit log, team members and invites, tokens and SSH key and sessions.

## Components

- `components/kit.tsx`: shared building blocks. `Panel`, `PageHeader`, `Crumb`, `Field`, `Toggle`, `Segmented`, `Choice`, `NumberInput`, `ErrorBanner`, `Notice`, `Loading`, `Empty`, `ConfirmDialog`, `CopyBlock`, `StatusDot`, `StatusBadge`, `RunStatus`, `Severity`, `Meter`, `Stat`, `KeyValue`. Check here before writing a new one.
- `components/ui/*`: shadcn/ui primitives (button, input, dialog, tabs, table, select, sheet, ...). Keep them close to upstream. Put app-specific styling in `kit.tsx`.
- `components/server/*`: the server page tabs (`status-tab`, `updates-tab`, `services-tab`, `containers-tab`, `logs-tab`, `history-tab`, `audit-tabs`, `settings-tab`), `banners.tsx`, and `use-access.ts`.
- Other shared pieces: `chart.tsx` (`LineChart`), `group-form.tsx`, `group-sharing.tsx`, `runs-table.tsx`, `team.tsx` (`CreateTeamDialog`, `useSessionReset`, `roleText`), `time.tsx` (`Ago`, `Until`, `When`).
- Import with the `#/` alias, for example `#/components/kit`.

## Data fetching

- `lib/api.ts`: `api()` returns the typed client from `@esa/api`. In the browser it calls the same origin. During SSR it calls `ESA_API_URL` directly and forwards the visitor's cookie.
- Wrap every call in `call(...)`. It returns the data or throws `ApiError` with `status`, `code`, `message`, and `field`. Show errors with `ErrorBanner` or `errorMessage(e)`.
- `lib/queries.ts`: every query lives in `q`, for example `q.me()`, `q.overview()`, `q.server(id)`. Add new queries there with `queryOptions`, and reuse the keys when you invalidate.
- Live pages poll: `q.overview()` and `q.server(id)` refetch every 15 seconds.
- After a mutation, invalidate the affected keys, for example `qc.invalidateQueries({ queryKey: ['tokens'] })`.
- Switching spaces calls `qc.clear()`, because every cached query belongs to the old account. Use `useSessionReset` from `components/team.tsx` for any flow that moves the session to another account.

## Permissions in the UI

- `useRole()` from `routes/app/route.tsx` gives `role`, `canAct` (owner or admin), and `isOwner`.
- `useServerAccess(server)` from `components/server/use-access.ts` gives `isOwn`, `canOperate` (runs, actions, logs), `canManage` (settings, helper, host key, removal), and `ownerTeam`.
- Hide or disable controls the user cannot use. The API is the real check. Never rely on the UI to enforce anything.
- Shared servers and groups carry `ownerTeam` and `access`. Show the owning team where names could repeat.

## Server side

- `server/proxy.ts`: forwards `/api`, `/auth`, and `/enroll` to `ESA_API_URL` (default `http://127.0.0.1:8080`). It drops hop-by-hop headers and headers a client must not set (`x-real-ip`, `forwarded`, `x-esa-client`, `x-forwarded-host`, `x-forwarded-proto`), caps bodies at 1 MiB, and times out after 60 seconds. Calls under `/api/v1/servers`, `/api/v1/certs`, and `/enroll/` wait on SSH, so they get 11 minutes and keep running when the browser disconnects.
- `server/mcp.ts`: the MCP server. Each tool calls the API with the caller's token and `x-esa-client: mcp`. See `docs/mcp.md`. Keep the rule that one token never gets both `get_logs` and `start_run`.
- `start.ts`: request middleware. CSRF check for server functions, plus security headers. In builds it sets a CSP with a per-request nonce: `script-src 'self' 'nonce-...'`, `connect-src 'self'`, `frame-ancestors 'none'`. Proxied paths keep the control plane's own headers.
- No inline scripts. No external origins for scripts, styles, fonts, images, or requests. Fonts come from `@fontsource-variable/*` packages.

## Styling

- Tailwind CSS 4, configured in `src/styles.css`. `@import 'tailwindcss' source('./')` scans only `src/` for class names. Classes built elsewhere, or assembled from string pieces, are not generated.
- Use the theme tokens: `bg`, `panel`, `line`, `ink`, `ink-2`, `faint`, `amber`, and the status colors `ok`, `warn`, `fail`, `down`, `pending`. The shadcn tokens point at the same palette.
- Headings: `font-display` (Big Shoulders), bold, uppercase. `PageHeader` does this for page titles.
- Labels and small captions: the `label` class (mono, uppercase, wide tracking). Numbers: `num` or `font-mono`.
- Amber is the one accent color. Use the status colors only for status.
- Containers: `Panel` or the `panel` class.

## Copy

- Plain, short sentences. Sentence case for buttons, labels, and messages.
- Say what happens: "Copy the token now. esa stores only a hash and cannot show it again."
- No marketing words, no exclamation marks, no emojis.

## Commands

From the repo root:

```sh
pnpm --filter @esa/web dev         # web on :3000, reads ../../.env
pnpm --filter @esa/web build
pnpm --filter @esa/web start       # run the built server from .output
pnpm --filter @esa/web lint        # eslint
pnpm --filter @esa/web typecheck   # tsc
pnpm format                        # prettier --write .
```

Prettier settings live in `prettier.config.js`: no semicolons, single quotes, trailing commas. The dev server needs the control plane running (`pnpm --filter @esa/esa dev`).

## Verifying changes

- There are no unit tests for the web app.
- Check every UI change in a real browser: Playwright driving Chrome, against `pnpm --filter @esa/web dev` with the control plane running.
- Check the pages you touched at desktop and phone widths, and as a viewer as well as an admin when controls depend on the role.
- The CSP is enforced only in builds. Run `pnpm --filter @esa/web build`, then `start`, when you change anything that loads scripts, styles, or fonts.
- Run `lint` and `typecheck` before you finish.
